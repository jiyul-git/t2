# 계정·개인정보 정리 설계

온라인 T2에서 무엇을 어디에 저장하고, 누가 보고, 어떻게 지우는지 정한다. 게이트웨이(`gateway/`)와 사용자별 게임 서버(`ui/server/ui_server.py`)가 대상이다.

## 1. 원칙

- **필요한 것만 저장한다.** 구글에서 받는 것 중 저장하는 것은 고유 ID(`sub`)와 이메일뿐이다. 이름·사진은 저장하지 않는다.
- **신원 정보와 게임 데이터를 나눈다.** 이메일은 게이트웨이의 계정 파일에만 있다. 게임 서버와 사용자 폴더에는 이메일이 없다.
- **다른 사람에게는 닉네임과 캐릭터만 보인다.** 이메일은 본인과 관리자만 본다.
- **칩은 게임용이다.** 현금 가치가 없고 사고팔 수 없다. 가입 화면에서 안내한다.
- **본인이 언제든 계정을 지울 수 있다.** 지우면 남는 것이 없다(백업은 보관 기간이 지나면 사라진다).

## 2. 가입 방식

허용 이메일 목록은 기본으로 끈다. 구글 계정이 있으면 누구나 가입할 수 있다.

| 설정 | 기본값 | 뜻 |
|---|---|---|
| `signup_mode` | `"open"` | `"open"`: 누구나 가입. `"invite"`: `allowed_emails`에 있는 계정만 가입 |
| `max_accounts` | `20` | 계정 수 상한. 넘으면 새 가입을 "정원이 찼습니다"로 막는다(기존 계정 로그인은 된다) |
| `max_backends` | `4` | 동시에 띄우는 게임 서버 수(서버 메모리 보호) |

열어 두어도 관리자는 계정을 **이용 중지**하거나 **삭제**할 수 있다(5장).

## 3. 저장 위치

```
~/t2_online/
  gateway/                  0700  게이트웨이 전용
    session.key             0600  세션 쿠키 서명 키
    accounts.json           0600  계정 목록(신원 정보는 여기에만)
  users/<uid>/              0700  사용자 게임 데이터(이메일 없음)
    tournaments.sqlite3           지갑(칩 잔액·원장)·대회 참가 기록
    profile.json                  닉네임·캐릭터·덱 색
    (메모 등 게임 서버가 쓰는 개인 파일)
  run/<uid>/                0700  게임 엔진 사본 + 진행 중인 대회 상태
  backups/                  0700  매일 백업, 7개 보관
```

### 3-1. 계정 파일 `accounts.json` (버전 2)

```json
{
  "version": 2,
  "accounts": {
    "u_3f9a...": {
      "sub": "1078...",              // 구글 고유 ID. 이메일이 바뀌어도 같은 사람
      "email": "a@gmail.com",        // 관리·연락용. 다른 사용자에게 보이지 않음
      "status": "pending",           // pending(구글 로그인만 함) / active(가입 완료) / disabled(이용 중지)
      "created": 1760700000,
      "last_login": 1760700000,
      "agreed_at": null,             // 가입 동의 시각
      "terms": null                  // 동의한 안내문 버전, 예: "2026-10"
    }
  },
  "by_sub": {"1078...": "u_3f9a..."}
}
```

- **`uid`는 무작위로 만든다**(`u_` + 16진수 20자). 지금은 세션 키로 만든 해시라서 `session.key`를 잃거나 바꾸면 모든 사람이 자기 칩을 잃는다. 앞으로는 `by_sub`로 찾는다.
- **닉네임은 저장하지 않는다.** 닉네임·캐릭터의 원본은 `users/<uid>/profile.json` 하나다. 설정에서 닉네임을 바꿔도 두 곳이 어긋나지 않는다.
- **옛 형식(`users.json`, 버전 1)에서 옮기기:** 게이트웨이가 처음 뜰 때 한 번 옮긴다.
  - 옛 기록에는 `sub`가 없으므로, 로그인할 때 옛 방식 uid(`HMAC(session.key, 'google:'+sub)`)로 찾아 `by_sub`에 연결한다.
  - `registered`가 있던 계정은 `active`로 옮긴다. `name`, `nickname`은 버린다.
  - 옛 파일은 `users.json.v1.bak`으로 남긴다.

### 3-2. 칩(스택)

- 사용자마다 `users/<uid>/tournaments.sqlite3`에 지갑이 하나 있다. 가입하면 기본 지급액(100,000칩)이 원장에 기록된다.
- 잔액은 원장 합계와 항상 같다. 바이인·상금은 원장 기록으로만 바뀐다(기존 `tournament_store.py` 규칙 그대로).
- 다른 사용자와 칩을 주고받는 기능은 없다.
- 관리자 칩 지급은 이번 범위가 아니다(필요하면 원장에 `admin_grant` 기록을 남기는 방식으로 추가).

## 4. 화면

- **가입 화면:** 닉네임·캐릭터·동의 체크. 동의 문구에 다음을 쓴다.
  > 저장하는 정보: 구글 이메일(계정 확인용, 다른 사람에게 보이지 않음), 닉네임·캐릭터, 칩과 대회 기록. 칩은 게임용이라 현금으로 바꿀 수 없습니다. 설정에서 언제든 계정을 삭제하면 모두 지워집니다.
- **설정 화면(로비):**
  - 내 계정: 로그인한 구글 이메일 표시
  - 로그아웃
  - 계정 삭제: 경고와 함께 "삭제"를 직접 입력해야 진행 → 삭제 후 로그인 화면으로

## 5. 게이트웨이 동작

| 요청 | 동작 |
|---|---|
| `POST /auth/google` | 토큰 확인 → `by_sub`로 계정 찾기(없으면 정원 확인 후 `pending` 계정 생성) → `disabled`면 거부 → 세션 쿠키 |
| `POST /auth/register` | `pending` 계정만. 프로필 생성 후 `active`, `agreed_at`·`terms` 기록 |
| `GET /auth/me` | `email`, `registered`(= active) |
| `POST /auth/delete` `{confirm:"삭제"}` | 게임 서버 정지 → `users/<uid>`, `run/<uid>` 삭제 → 계정 기록 삭제 → 쿠키 제거 |
| 모든 요청 | 세션의 계정이 없거나 `disabled`면 401(쿠키 제거) |

로그(`[gw] ...`)에는 IP·경로·상태만 남고 이메일은 남기지 않는다.

## 6. 관리 도구 `gateway/admin.py`

게이트웨이 설정 파일을 같이 읽는다(`--config`).

```
python3 gateway/admin.py list             # uid, 이메일, 닉네임, 칩, 상태, 마지막 로그인
python3 gateway/admin.py disable <uid|이메일>
python3 gateway/admin.py enable  <uid|이메일>
python3 gateway/admin.py delete  <uid|이메일>   # 확인 질문 후 삭제
python3 gateway/admin.py backup           # backups/t2-YYYYMMDD-HHMM.tar.gz, 7개만 보관
```

- `disable`·`delete`는 게이트웨이가 켜져 있으면 다음 요청부터 적용된다(게이트웨이가 요청마다 계정 상태를 다시 읽는다).
- `list`의 칩은 지갑을 읽기 전용으로 연다.
- `backup`은 지갑을 SQLite 백업 기능으로 복사해, 게임 중에도 깨지지 않은 사본을 만든다. 백업 파일 권한은 0600.

## 7. 시험

`gateway/verify_gateway.py`에 다음을 확인한다.
- 열린 가입: 목록에 없는 계정도 가입된다. `max_accounts`를 넘으면 새 계정은 막히고 기존 계정은 들어온다.
- 초대 모드: 목록에 없는 계정은 막힌다.
- `session.key`를 바꿔도(세션은 끊기지만) 다시 로그인하면 같은 지갑이 나온다.
- 옛 `users.json`에서 옮긴 계정이 로그인하면 원래 폴더를 이어 쓴다.
- 이용 중지 계정은 쿠키가 있어도 막힌다. 다시 풀면 들어온다.
- 계정 삭제 후 폴더·계정 기록이 없고, 같은 구글 계정으로 다시 들어오면 새 가입부터 시작한다.
- `accounts.json`과 사용자 폴더의 권한, 사용자 폴더에 이메일 문자열이 없는지.
- `admin.py list/disable/enable/delete/backup`.
