**ft60 이 바이트 그대로인지 확인한 방법**
1. ft60 씨앗 표를 새 코드로 다시 만들어 저장소의 `data/ft60/step0/tables/` 와 `git diff` → 차이 없음.
2. 끝점 고르기·상수(`N_TERMS`, 경로, 패널, 시간 추정)를 옛 파일과 같은 입력으로 비교 → 같음. 커밋된 ft60 0단계 묶음 40개와도 같은 선택.
3. `ft_solve.sh` 는 가짜 솔버로 돌려 설정 파일·인자·환경 변수를 옛 스크립트와 비교 → 같음(차이는 내 시험 폴더 경로뿐).
4. `ft_board.py` 는 상수·경로·커밋 문구를 옛 파일과 비교 → 스택 60 에서 같음.
- **못 한 것**: 전체 `prepare` 의 끝까지(ft60 체크포인트가 없어서). 도달 확률 출력은 ft60 값과 비교하지 못했다.

## 3. 재구성한 도구: `t2_ft_export.rs`

## 6. 보드 세션 한 번에 실행 (n 만 바꾼다)


- 마지막 실행만 괄호 안에서 떼어 내므로 앞의 준비 단계는 앞에서 끝까지 돌고(실패하면 멈춤) 실행은 뒤로 간다. 커밋 꼬리표에 세션 id 를 넣으려면 `FT_SESSION=<id>` 를 `setsid` 앞에 붙인다(선택).
- 준비 끝줄 `FT_BOARD_SETUP_OK` 가 나와야 실행으로 넘어간다(`&&`). 진행: `tail -3 /home/user/gto_ckpt/ft30_board.log`, 끝줄 `FT_BOARD_ALL_DONE`.
- **추적되는 대기 작업을 늘 하나 켠다**(`run_in_background=true, timeout=7100000`): `until ! pgrep -f ft_board.py > /dev/null; do sleep 120; done; tail -5 /home/user/gto_ckpt/ft30_board.log`. 알림 때 `ft_board.py` 가 살아 있으면 대기 작업만 다시, 죽었으면(끝줄이 `FT_BOARD_ALL_DONE` 아님) 같은 실행 명령을 다시.
