## 1. 결론 먼저

- **주범은 레인지 폭이 아니다.** 동기화 전/후 레인지로 같은 시드를 돌려도 탑페어 에쿼티(플랍 0.54 vs 0.54)와 벳 빈도(플랍 26% vs 23%)가 거의 같다.
- **주범은 "밸류 문턱"의 단위 불일치다.** 문턱(0.66 / 0.80 / 0.50)은 **상대 한 명 기준 승률**의 크기로 정해져 있는데,
  지금 들어가는 에쿼티는 **상대 전원을 동시에 이겨야 하는 승률**(3인 팟이면 대략 한 명 기준 승률의 제곱)이다.
  그런데 문턱은 인원이 늘수록 **오히려 올라간다**(+0.06~0.07/명). 두 번 깎는 셈이다.
- 그 결과 3인 팟 탑페어(평균 에쿼티 0.52, 공정 몫 0.33)가 플랍에서 70%가 "약한 패 구간"으로 떨어지고,
  거기서 팟컨트롤(72% 확률) 또는 쇼다운 계획 → 선공권이 없으면 **벳 확률 0** 으로 간다.
  플랍에서 이렇게 정해진 계획은 턴·리버에서 거의 풀리지 않는다(계획 유지 + 강등만 쉬움).

## 4. 반사실 (같은 기록을 다시 분류만 함, 동작 불변)

플랍 탑페어가 어느 구간에 들어가는가 (v3/v2=밸류, 중간, 약함):

| 가정 | 밸류 | 중간 | 약함 |
|---|---|---|---|
| 현재 그대로 | 7% | 22% | **70%** |
| 동기화 이전 레인지로 돌린 실제 런 | 4% | 35% | 62% |
| 넓은 기준 레인지(상위 35%) 대비 에쿼티 | 0% | 56% | 44% |
| 완전 랜덤 레인지 대비 에쿼티 | 15% | 59% | 26% |
| 인원 가산만 제거 | 7% | 59% | 33% |
| 인원 가산 제거 + rel 을 예전(합집합) 방식 | 19% | 48% | 33% |
| **에쿼티를 헤즈업 환산(√, 3인)** + 인원 가산 제거 + 합집합 rel | **86%** | 15% | 0% |

→ 레인지를 넓혀 봐도(35%·랜덤) 탑페어는 여전히 밸류 문턱에 못 미친다. 문턱이 헤즈업 단위라는 것을 맞춰야 풀린다.
턴은 같은 순서로 0% → 69%, 리버 7% → 67%.

## 5. 고칠 방향 (적용하지 않음 — 선택용)

1. **문턱을 "공정 몫" 기준으로 바꾸기** (가장 근본). 3인 팟 공정 몫 0.33을 기준으로 에쿼티를 헤즈업 환산(예: eq^(1/N) 또는 eq ÷ 공정 몫)해서 기존 0.66/0.80/0.50 과 비교하고, 인원 가산(+0.06/명)은 지운다. 이미 밸류 레이즈 판정(`value_raise_qualification`)은 공정 몫 1/(N+1)을 쓴다. 바뀌는 것: 탑페어·오버페어가 플랍에서 주로 밸류 계획을 받아 벳 빈도가 크게 오름(위 표 86%가 상한, 실제는 벳 확률 곡선을 한 번 더 거침). 회귀 기준선 전부 다시 잡아야 함.
2. **인원 가산만 제거 + rel 구간을 전원 기준 rel 에 다시 맞추기** (중간). `multiway_value_thresholds` 의 +0.06/0.07 을 0 으로, `relative_strength_value_threshold_shift` 의 0.45/0.85 를 전원 기준 rel 분포에 맞게 낮춤. 바뀌는 것: 약한 구간 70% → 약 33%, 대부분 중간 구간으로 올라가 얇은 밸류/블락벳 경로가 열림. 변화 폭이 1번보다 작고 예측 쉬움.
3. **선공권 없는 쇼다운 계획의 0% 를 풀기** (국소). 멀티웨이에서 메이드 탑페어가 쇼다운 계획이면 프로브/리드 확률을 0 대신 작은 값(성향 기반)으로. 바뀌는 것: 체크 56건 중 23건이 걸린 지점만 손댐. 원인(문턱)은 그대로라 근본 해결은 아님.

권장 순서: 2 → (확인 후) 1. 3은 2·1 이후에도 남으면.
