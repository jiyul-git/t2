## 1. 무엇을 했나
- 솔버 패치 `tools/gto_brick/t2_brick_merge.patch` (계산 브랜치 `claude/resume_p100_flat_20261030` 의 `vendor/gtopen` 에 `git apply`).
  `T2_BRICK_MERGE=1` 일 때만 켜짐. 꺼져 있으면 원래 코드 경로 그대로(추가된 분기는 모두 `brick: None` 검사 뒤).
  전략 저장 패치(`claude/precision_runner_20261031` 의 `t2_cont_panel_strategy.patch`)와 같이 적용됨을 확인(`git apply --check` 통과).
- 켜면: 턴·리버 카드 분기에서 브릭 카드들을 같은 무늬끼리 묶어 대표 카드(가운데 카드) 한 갈래만 푼다.
  묶인 카드 c 의 값 = 대표 갈래에서 **숫자 바꿔치기**(대표 숫자 ↔ c 숫자, 모든 무늬)한 핸드의 값
  (예: 2c 턴의 22 = 4c 턴의 44, A2s = A4s). 각 카드는 원래 확률(1/45, 1/44)을 그대로 가짐 = 대표가 장 수만큼 가중.
  전략 파일용으로 풀이 뒤 대표 갈래를 묶인 갈래에 같은 바꿔치기로 복사(`ensure_symmetric`).
- 출처키에 `brick_merge`(규칙 이름·기준값) 가 들어가므로 묶음 결과와 정확한 결과가 섞여 재사용되지 않는다.
  결과 파일 `brick_merge.contexts` 에 보드마다(턴 1개 + 턴 카드별 리버 49개) 브릭 카드, 탈락 이유 수, 핸드 영향 기록.
- 규칙 `brick_v1` (코드 `crates/solver/src/brick.rs`, 비교 전에 고정):
  1. 보드에 같은 숫자 없음(페어 보드 X)
  2. 보드 두 번째로 높은 카드보다 낮음
  3. 무늬: 턴 = 보드에 없는 무늬만(드로우 상태 변화 X), 리버 = 그 무늬가 보드에 1장 이하(플러시 불가)
  4. 스트레이트: 그 카드로 스트레이트가 새로 완성되거나(턴은) 새 원카드 아웃이 생기는 콤보가 각 레인지의 2% 이하
  5. (코디네이터 보강) 바꿔치기 비중 차이: 그 숫자·대표 숫자를 든 콤보의 레인지 비중 차이 Σ|w(h)−w(σh)|/2 ÷ 레인지가 양쪽 모두 1% 이하.
     근거: 비중이 어긋난 콤보는 셋/페어 핸드라 값 차이가 팟 하나(100bb 에서 약 10bb)까지 남 → 1% × 10bb ≈ 0.1bb < p100 CO 정밀 패널 오차 U(144) 약 0.15bb.
  - 기록(보드·카드마다): `hold[p].set_share`(포켓 페어 → 셋 비중), `pair_share`(한 장 → 페어 비중), `swap_mismatch`(규칙 5 값), `merged`.
