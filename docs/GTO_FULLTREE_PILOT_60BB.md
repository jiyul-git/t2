## 3. 방법 (바깥 고정점, 기존 루프 규칙 v4·precision 표준을 전체 트리로)
엔진: vendored gtopen 의 `t2-cont` 기능 — 전체 트리의 헤즈업 pot-share 끝점에 클래스별 값 표(`t2_hu_continuation_table_v1`, gross_share)를 노드 번호로 끼운다(manifest).
표가 없는 끝점은 부모와 같은 정적 값(`realization: static`).
- **0단계(시작)**: 표 = BB 보정 값(60bb 기존 루프 4개 — BTN·CO·HJ·LJ 2.5 오픈 vs BB 의 플랫 끝점과 3벳콜 끝점, 계산 브랜치의 `progress/<id>/state.json` 표 — census·`claude/p3bet_c_20261026`·`claude/resume_p3bet_20261030` 에 있는지 시작 전에 확인, 없으면 그 끝점은 정적으로 시작; 같은 cfg 라 노드 번호가 같다) + 나머지 정적.
  전체 트리 풀이 → 고른 헤즈업 끝점마다 도착 레인지 내보내기(`t2_cont_terminal @multi`) → 끝점마다 A 72 + B 72 보드 풀이(전략 저장 패치 `t2_cont_panel_strategy.patch`, `claude/precision_runner_20261031`) → V_A, V_B, V_A∪B, U.
- **k단계**: 새 표 = 0.5·T_k + 0.5·V_A∪B(처음 표가 생기는 끝점은 V_A∪B 그대로, D/U 가 오르내리는 끝점은 0.25) → 전체 트리 다시 풀기(앞 단계 체크포인트에서 이어서, 정확 gap ≤ 0.010bb) → 다시 레인지 → 보드.
- **통과(precision 표준 그대로)**: 고른 모든 끝점·자리에서 ① D = |V_A∪B − V_사용| ≤ U(144) ② |V_A − V_B| ≤ 2√(U_A²+U_B²) ③ 뿌리(이 시범에서는 "연결 후보 노드" = BB 외 수비 노드, 오픈 받은 SB·BB, 3벳 받은 오프너)에서
  A만·B만으로 푼 전략 차이 ≤ 5%p 인 콤보 ≥ 95%. 개정 8(상대 1콤보 미만 끝점-자리 면제)·개정 12 그대로. **평균값을 precision 이라 부르지 않는다.**
- 3명 이상 끝점: 정적 값 그대로, 기록에 `approximate_multiway` 표시. 단계마다 남기는 것: 3명 이상 도달 확률(사람 수별), 상위 끝점 목록,
  **영향 측정**: 같은 표로 `realization: raw`(R=1, 표 없는 끝점에만 효과)로 한 번 더 풀어 정적 vs raw 차이를 연결 후보 노드에서 클래스별로 잰다(간이 값이 결론을 얼마나 흔드는가의 범위).
  차이 > 10%p 인 콤보가 10% 넘는 노드는 "3명 팟에 민감" 표시 → 연결 후보에서 뺀다(보정 계수 만들지 않음).
- 기존 짝별 루프와 다른 점(위험): 짝별 루프 v4 는 끝점 값을 상대 레인지에 반응하는 행렬로 감쇠했지만 전체 트리의 `t2-cont` 표는 **고정 값**(한 단계 동안 상대 레인지에 반응 안 함)이다.
  순환이 더 잦을 수 있다 → 감쇠 0.5/0.25 로 시작, 0단계→1단계에서 D/U 가 줄지 않으면 멈추고 보고(행렬 지원은 엔진 기능 추가 = 별도 승인 사항).

## 4. 끝점 고르기
- 단계마다 그 단계 전체 트리 풀이의 도달 확률로 다시 고른다: **헤즈업 끝점 중 도달 ≥ 3e-4(지금 65개)** 를 기본으로, 비용을 줄이려면 ≥ 1e-3(40개).
- 고르지 않은 헤즈업 끝점: 앞 단계 표가 있으면 그대로, 없으면 정적. 그 몫(헤즈업 도달 중 표 없는 몫)을 기록한다.
- 새로 기준을 넘은 끝점: 다음 단계에 추가하고 그 끝점은 그 단계를 "0단계"로 센다(통과 판정은 표가 한 번 갱신된 뒤).

- 묶음 = (끝점 하나, 패널 A 또는 B) = 72보드 ≈ 3컨테이너 시간 → 단계당 묶음 80개(40 끝점) / 130개(65 끝점). 2시간 작업 제한: 보드마다 결과 파일이 남으므로 다시 실행하면 이어진다(precision_runner 방식).
- 주고받는 곳: 조정 브랜치(예 `claude/fulltree60_coord`)에 `step<k>/inputs/`(끝점 레인지·cfg·패널 sha), `step<k>/assign.tsv`(묶음 → CLAIM 세션), 보드 세션 브랜치 이름 규칙 `claude/fulltree60_s<k>_<세션짧은id>`.
  모으는 세션은 assign.tsv 의 모든 묶음이 결과 sha 와 함께 들어와야 다음으로 간다. 입력 sha 가 다른 결과(옛 단계 레인지로 푼 것)는 받지 않는다.
- 같은 세션에 두 묶음을 동시에 주지 않는다(한 컨테이너에 t2_cont_panel 하나).

## 7. 멈춤 기준 (계산 전에 고정)
- **단계마다 멈춰 보고**(PREC_STAGE_LIMIT=1 방식): 0단계가 끝나면 무조건 멈춘다. 다음 단계는 코디네이터 확인 후.

- 실패로 멈춤: 0단계 + 3단계 안에 못 통과 → `precision_failed`(연결할 값 없음으로 보고, 평균 안 만듦) / 플랍이 CFR+ 재시도 후에도 안 풀림 → 그 끝점 실패, 그대로 보고 /
  0→1단계에서 끝점 D/U 가 줄지 않음(고정 값 표의 순환 신호) → 멈추고 보고 / 같은 오류로 두 번 연속 죽음 → 원인 보고.
