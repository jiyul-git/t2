# C. PREFLOP_ORDERING_DUPLICATION — `PCT`(pf_rank) vs `bot._pf_score`

기준 `test` `d284a9e`. 읽기 전용이며, 행동이 바뀌는 통합은 하지 않았다.

## 1. 두 순서표

| | `preflop.PCT` (pf_rank.json) | `bot._pf_score` → `bot._SCORED` |
|---|---|---|
| 형태 | 169 클래스 → 누적 콤보 백분위(0~1). 표 | 공식: `2·높은랭크 + 낮은랭크`, 페어 +22, 수티드 +4, 갭 1~4 이면 +(5−갭). 1326 콤보를 점수 내림차순 정렬 |
| 출처 | 기록 없음(최초 커밋 `39bbc966` 에 이미 있음) | 기록 없음. bot.py "range-aware equity" 절의 헬퍼 |
| 같은 점수 처리 | 클래스 단위로 하나의 값 → 슬라이스가 클래스를 쪼개지 않음 | 점수 동률을 **덱 나열 순서**로 깬다. 슬라이스 경계에서 같은 클래스가 수트에 따라 갈린다(30%: 98s 2/4, K8o 5/12 / 35%: Q8o 10/12) |
| 소비처 | A 문서 #1~#19 전부(RFI·디펜스·콜오프·레인지 구성·블로커·관찰 등) | `bot.range_combos(pct)` 하나뿐이고, 그 소비처는 아래 셋 |

`range_combos` 의 production 소비처:

| 소비처 | 줄 | 언제 쓰나 | 질문 |
|---|---|---|---|
| `plan` 기록용 equity (`_normalize_opp_pools` 를 쓰는 두 함수) | plan.py:424, 462 | 그 상대의 perceived range 가 비었을 때 `range_combos(0.35)` | "모르는 상대의 중립 프리플랍 레인지" |
| `plan` 대응 판단의 equity 풀 | plan.py:2268 | 같은 fallback(빈 레인지일 때) | 같음 |
| `bot.equity_vs_betting` → `betting_range(base_pct)` + 콜러 `range_combos(0.30)` | bot.py:439, 462 / plan.py:2331 | 상대 레인지(`opp_range`)가 없을 때의 fallback equity. 어그레서는 `(0.22, bluff)`, 콜러는 `(0.30, 5)` | "레인지를 모를 때 벳한 사람/콜한 사람의 레인지" |
| `bot.equity_vs_range` | bot.py:236 | production 호출부 없음 | — |

## 2. 같은 질문인가

두 순서표 모두 "프리플랍 핸드를 강한 순으로 세워 상위 X% 를 레인지로 삼는다"에 답한다. **같은 질문이다.**
- `PCT` 는 관찰된 액션으로 상대 레인지를 만들 때 쓴다.
- `_pf_score` 는 그 관찰 정보가 없을 때의 fallback 이다.

fallback 은 "정보가 없을 때"를 뜻할 뿐 질문을 바꾸지 않는다. 그래서 순서가 둘일 이유가 없다.

정량 비교(`eq_vs_random_169.json` 의 HU equity 순서를 제3의 기준으로 함께 표시):

| 상위 슬라이스 | PCT ∩ _pf_score | PCT ∩ equity | _pf_score ∩ equity |
|---|---|---|---|
| 10% | 0.88 | 0.79 | 0.83 |
| 22% | 0.91 | 0.81 | 0.88 |
| 30% | 0.91 | 0.79 | 0.86 |
| 35% | 0.94 | 0.87 | 0.90 |
| 50% | 0.94 | 0.89 | 0.95 |

클래스 단위 Spearman 상관:
- PCT ~ _pf_score 0.962
- PCT ~ equity 0.934
- _pf_score ~ equity 0.980

차이가 나는 대표 지점:
- `_pf_score` 상위 20: …AKo 12위, AQo 15위, KQo 18위
- `PCT` 상위 20: AKo 17위, 66·55 포함, AQo 없음
- `_pf_score` 는 하이카드 공식이라 HU equity 쪽에 더 가깝다. `PCT` 는 페어·수티드 커넥터를 더 높게 둔다.

## 3. 판정

- **같은 질문, 순서 둘 → 중복(R2-A3).** canonical ordering 하나로 통합할 후보다.
- 통합하면 fallback 레인지가 상위 35% 기준 약 6%의 콤보만큼 바뀌고, 그만큼 행동이 바뀐다. 그래서 **이번 단계에서는 통합하지 않는다.**
- canonical 후보는 `PCT` 다. 근거는 셋이다.
  - 모든 1차 소비처가 이미 쓴다.
  - 클래스 단위라 수트 의존 분할이 없다.
  - 순서로 충분한 소비처에서 재현율이 0.90 이다(A 1절).
- `_pf_score` 의 동률 분할(같은 클래스가 수트에 따라 레인지 안팎으로 갈림)은 의미 결함이다. 통합하면 함께 사라진다.
- 이름 분리 대안(서로 다른 질문으로 보고 둘 다 남기기)은 근거가 없다. fallback 레인지가 "필드 평균 레인지"라는 다른 질문을 의도했다면 그 근거(필드 VPIP 등)가 있어야 하는데, 지금은 고정 0.35/0.30/0.22 뿐이다.
