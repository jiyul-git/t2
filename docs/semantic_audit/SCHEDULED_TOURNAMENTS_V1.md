## 동작

- 코드·화면을 다시 설치해도 개인 잔액, 입출금 내역, 참가 내역과 대회 상태를 유지한다.
- 로비의 수동 새 게임 생성 UI를 예정/진행/내 참가 목록으로 교체했다.
- 예약 시 바이인 칩을 차감한다. 시작 전 예약 취소는 같은 칩을 한 번만 환불한다.
- 대회는 서버 실제 시각을 따르며, 접속하지 않아도 봇들은 진행한다. 등록한 HERO 자리는
  체크 가능한 경우 체크하고 나머지는 폴드한다. 블라인드·안테는 실제 엔진에서 낸다.
- 서버가 중단됐던 시간은 재시작 후 저장된 시드/필드에서 따라잡는다. 레이트 바이인은
  먼저 영구 접수하고 요청 시각 이후의 완료 핸드에서 착석한다. 동기화 중에는 입장 대기를
  표시하며 자동으로 이어간다. 기존 봇의 스택/탈락을 새 필드로 대체하지 않는다.
  따라잡는 동안 기존 필드의 상금권 도달로 등록이 먼저 닫힌 경우 미착석 참가비를 한 번만 환불한다.
- 레이트 등록은 서버 시각이 마감 시각보다 엄격히 작을 때만 받는다.
- V1의 리바이인은 **탈락 후 같은 대회에 유료 재참가하는 리엔트리**다. 생존 중 스택을
  추가 구매하는 rebuy/add-on은 없다. 새 참가 번호와 pid를 만들고 기존 탈락 기록을 보존한다.
- 늦은 참가/재참가는 테이블의 진행 중 팟에 들어가지 않고 완료 핸드의 경계에서 착석한다.
  재접속도 진행 중이던 자동 핸드가 완료된 후 수동 플레이로 전환한다.
- 수동 액션 제한 시간은 액션 바가 표시될 때부터 보장한다. 동일 결정의 새로고침으로
  마감을 연장할 수 없다. 미접속/표시 실패에는 서버 마감이 적용된다. 탈락 직후 정산 중
  브라우저가 닫히거나 서버가 재시작돼도 정산과 나머지 대회 진행을 복구한다.
- 최대 1,000엔트리, 9-max. 재참가도 엔트리와 총 토너 칩, 상금 풀에 더한다.
- 55분 플레이/5분 브레이크는 대회 시작에 맞춰 공통 적용한다. 개인별 휴식 건너뛰기는 없다.
- 한 UI에서 한 HERO 테이블을 조작한다. 다른 예약 대회는 자동 체크/폴드로 계속 진행한다.
- 등록 마감 또는 상금권 도달 시 상금 표를 고정한다. 확정된 탈락 순위/우승에 따라 칩을
  개인 지갑에 한 번만 입금한다. 상금 비율을 다시 정규화하고 정수 칩으로 배분해 풀의 합계를 보존한다.

## 임시 운영값

최종 경제 밸런스를 확정한 값이 아니다. 현재 설정은 다음과 같다.

2026-10-06 KST 후속: 전체 기본 일정은 **2시간에 한 대회**, 표준 → 터보 → 딥스택 순서다.

| 종류 | 한국 시간 시작 | 바이인 | 초기 봇 수 | 시작 후 등록 기간 | 재참가 |
|---|---:|---:|---:|---:|---:|
| 표준 | 00:00 / 06:00 / 12:00 / 18:00 | 1,000칩 | 99명 | 60분 | 최대 2회 |
| 터보 | 02:00 / 08:00 / 14:00 / 20:00 | 500칩 | 44명 | 30분 | 최대 2회 |
| 딥스택 | 04:00 / 10:00 / 16:00 / 22:00 | 5,000칩 | 179명 | 90분 | 최대 2회 |

최초 지급은 100,000칩이며 기존 계정에는 다시 지급하지 않는다. 참가자 스택과 개인 지갑은
별개다. 현재 상금 풀은 `(초기 봇 엔트리 + 취소하지 않은 HERO 엔트리) × 해당 대회 바이인`이며
별도 수수료는 없다. 봇의 참가비는 게임 내 가상 필드의 기여금이다.

`T2_INITIAL_CHIPS`는 새 지갑의 첫 지급만 설정한다. 개인 데이터 폴더의 `schedule.json`은 위
템플릿 키(`fmt`, `minute`, `buyin`, `bot_entries`, `late_minutes`, `max_reentries`)를 사용한다.
선택 키 `interval_hours`(1~24), `hour_offset`(0~interval_hours-1)은 UTC epoch 시간의
나머지로 해당 포맷의 반복 시각을 정한다. 생략하면 기존 매시 `minute` 설정을 유지한다.
기본값은 세 종류 모두 6시간 간격이며 UTC offset 3/5/1로 한국 시간에 맞춘다.
각 대회에 규칙 사본을 저장하므로 설정/코드 변경으로 이미 생성된 대회의 바이인이나 마감이 바뀌지 않는다.
기존 20분 기본 일정의 빈 슬롯만 런타임에서 정리한다. 참가/취소 영수증이나 원장 참조가 있는
대회는 그대로 유지하며, 사용자의 명시적인 `schedule.json`도 그대로 유지한다.

## 저장과 배선

- `personal_data.py`: 시스템 밖의 개인 데이터 위치와 설치 연결 정보를 확인한다. 기존 지갑이
  없거나 거래 원장이 맞지 않으면 업데이트/실행을 중단하고 기존 파일을 보존한다.
- `tournament_store.py`: SQLite 지갑·거래 원장·대회·엔트리·정산. 잔액은 정수, 음수 금지.
- `scheduled_runtime.py`: 기존 `live2._vclock_table_task`와 시간순 이벤트 정산을 재사용하는
  백그라운드 필드. 테이블 작업은 기존 `T2_TABLE_WORKERS` 풀에서 병렬 계산한다.
- `fieldsim.Field._play_table`: `sitout_pids`에 속한 실제 플레이어는 봇 전략 대신 체크/폴드 입력.
- `live2.STATE_STORE`: 예약 대회에서는 SQLite가 상태의 원본이다. JSON 상태는 기존 UI/도구
  호환용 복사본이다. CLI/기존 연습 게임의 기본 JSON 경로는 그대로 동작한다.
- `ui/server/ui_server.py`: 스케줄러, 진입 대기, 자동 액션 마감, 기존 플레이 워커의 단일 게시자.
- `ui/web/lobby.*`, `ui/web/app.js`: 칩 잔액/거래, 예약/등록/재참가, 정산 결과와 로비 이동.
- 두 `setup_run_dir` 허용 목록에 새 모듈을 넣었다. 사용자 데이터는 복사하거나 삭제하지 않는다.

최초 설치와 업데이트는 별도 패키지/명령이다. 표준 설치 경로는 `T2/system`과 `T2/personal`이다.

| 경로 | 내용 | 업데이트 시 처리 |
|---|---|---|
| `T2/system/` | 게임 코드, 화면, 정적 자료, 기존 UI 호환 상태 파일 | 시스템 파일만 교체 |
| `T2/personal/` | 지갑 SQLite, 거래/참가 내역, 대회 상태 원본, `schedule.json`, `installation.json` | 보존 |

`T2-install.zip`은 시스템과 개인 폴더 안내, `install.py`를 포함한다. 지갑 DB는 배포하지 않고
최초 설치 시 해당 사용자의 컴퓨터에서 한 번 생성/지급한다. 재설치에서는 기존 지갑을 유지한다.
`T2-update.zip`에는 시스템과 `update.py`만 있으며 개인 폴더나 지갑 DB는 포함되지 않는다.
업데이터는 기존 지갑을 검사한 뒤 시스템 파일만 복사한다. 개인 파일의 내용을 변경하거나
초기 지급을 실행하지 않는다. 검사도 DB/WAL의 임시 복사본에서 수행해 원본 SHM까지 보존한다.

`installation.json`의 상대 경로 연결로 시스템과 개인 폴더를 함께 옮겨도 같은 지갑을 사용한다.
최초 설치의 `--personal-dir`로 별도 영구 폴더를 지정할 수도 있다. 연결 정보/지갑이 사라지거나
손상되면 새 지갑으로 대체하지 않는다. 설치된 `system`에서는 연결 정보 없이 `T2_DATA_DIR`만으로
다른 새 지갑을 시작할 수 없으며, 연결된 지갑과 환경 변수 경로가 다르면 중단한다.

수동 `setup_run_dir` 실행본은 코드 밖의 OS 사용자 데이터 폴더를 기본으로 사용한다.
Linux/Termux는 `$XDG_DATA_HOME/T2/personal` 또는 `~/.local/share/T2/personal`,
macOS는 `~/Library/Application Support/T2/personal`, Windows는 `%LOCALAPPDATA%/T2/personal`이다.
이 수동 실행본에 한해 `T2_DATA_DIR`로 코드와 분리된 경로를 지정할 수 있다.
과거 실행본의 `userdata/tournaments.sqlite3`는 `--migrate-from`으로 명시적으로 이전한다.
기존 지갑이 발견되면 임의로 새 지갑을 만들지 않으며, 이전에는 SQLite backup을 사용해
커밋된 WAL·거래·참가·대회 상태와 `schedule.json`을 보존하고 원본 지갑을 남긴다.
업데이트와 이전 전에 서버를 종료한다. 실행 명령은 [UI 설치 안내](../../ui/README.md#개인-지갑을-분리한-설치와-업데이트-test-2026-10-05)에 있다.

SQLite WAL, `synchronous=FULL`, 명시적 트랜잭션을 사용한다. 최초 계정 생성과 지급도 한
트랜잭션이다. 첫 스키마는 `user_version=1`이고 향후 스키마 변경은 기존 데이터를 마이그레이션해야 한다.

바이인: 원장 기록 + 잔액 + 참가 내역을 같은 트랜잭션으로 쓴다. 정산: 확정 필드 상태 +
상금 원장 + 잔액을 함께 쓴다. 원장 키는 참가 번호를 포함하며 고유 제약으로 재요청을 막는다.
워커는 파일/지갑에 직접 쓰지 않는다. 부모가 `revision`을 비교해 예약/수동 액션 뒤의 낡은
결과를 버리고, 좌석 배정과 상태를 함께 확정한다.

API: `GET /api/wallet`, `GET /api/lobby`, `POST /api/register`, `/api/reenter`,
`/api/enter`, `/api/unregister`. 금액/상금/레벨/시드는 서버가 소유하며 요청 본문의 금액은 사용하지 않는다.
`/api/new`는 일반 UI에서 막았다. 격리한 기존 연습 검증만 `T2_ALLOW_PRACTICE_NEW=1`로 사용하며,
예약 대회가 활성화됐으면 이 플래그로도 새 게임을 덮어쓸 수 없다.

## 후속 수정: 대회 간격과 입장 동기화 (2026-10-06 KST)

20분 기본 일정이 만들어 낸 미참가 대회가 단일 스케줄 워커에 쌓이고, 진행 스냅샷이
현재 시각의 2초 이내여야 바이인할 수 있는 조건 때문에 느린 기기에서 `synchronizing`이
반복됐다. 착석 후 UI 인수 조건도 매번 현재 시각으로 이동해 입장을 다시 지연시켰다.

- 기본 일정을 두 시간 간격으로 줄였으며, 미참가·등록 마감 대회는 워커 큐에서 제외한다.
- 입장 대기/선택 대회를 먼저 따라잡고, 같은 우선순위 안에서는 순환한다.
- 레이트 참가비와 요청 시각을 원장/영수증에 함께 접수한다. 재요청은 중복 차감하지 않는다.
  기존 필드가 요청 시각에 도달한 뒤 완료 핸드에서 착석하고, UI는 입장 요청 시각을 기준으로 인수한다.
- 등록이 자연 종료된 필드에 새 자리를 붙이지 않는다. 미착석 영수증은 상태 저장과 같은
  트랜잭션에서 환불/취소한다. 환불 안내에는 로비 이동 버튼을 표시한다.
- `T2_UI_DEFER=0`에서 풀이 없어 정산이 영원히 대기하던 문제도 수정했다.
  같은 `compute_vclock_ahead` 결과를 동기 실행해 수확하되 필요한 현재 범위만 계산한다.
  비동기 풀이 켜진 경우 기존 선계산 경로를 유지한다.
