227개 의미 레코드: 선언된 capability 37개에 코드의 독립적인 판단 질문, 계산, 관측, 상태/기질을 더했다. 함수 수와 개념 수는 같지 않다. 같은 함수가 여러 행에 등장하면 여러 의미를 구현한다는 뜻이다. `FUNCTION_CALL_CENSUS.json`은 268개 Python 파일 전체를 AST 분석한 함수/호출 증거이며 동적 dispatch의 완전한 증명은 아니다. 실제 핵심 호출은 별도로 읽고 연결했다.

**지식 표기**: M=직접 수학/MC 계산(가정과 근사 포함), K=코드에 쓰인 GTO-inspired 폭 prior(독립 solver 검증을 뜻하지 않음), H=작성된 poker/인간 heuristic(검증된 최상위 플레이어 empirical data 아님), E=실제 시뮬레이션 관측 통계. 요청한 A/B/C 출처를 임의로 solver/human 연구로 승격하지 않는다.

ACTIVE는 기본 경로에서 값이 소비됨을 뜻하며 모든 spot에서 행동을 바꾼다는 뜻은 아니다. SHADOW는 계산/기록되지만 전략 consumer 없음. FALLBACK은 대체 runtime/입력 부재 경로. DEAD는 production 의미 영향 없음(호출 자체가 남을 수도 있음). OPT-IN은 기본 OFF. DUPLICATED/SEMANTICALLY_OVERLOADED는 active 경로의 구조 상태도 표현한다.

## 2차 정리: defend 판단 계산 경계

`preflop.defend_thresholds`는 공통 producer를 유지하고 다음 순수 계산을 호출한다. 모든 수치와 계산 순서를 보존한다.

| 함수 | 입력 → 출력 | 의미 |
| --- | --- | --- |
| normalize_defend_prior_widths | attack/continue 폭, calibrated 여부 → 정규화한 두 폭 | 기존 prior clamp/saturation 계약 |
| adjust_defend_widths_for_callers | profile, 두 폭, 콜러 수 → 보정한 두 폭 | 콜러·squeeze 문맥 |
| adjust_defend_widths_for_short_stack | 두 폭, bb → 보정한 두 폭 | 기존 short-stack attack/call 구간 |
| tighten_defend_widths_for_raise_level | 두 폭, raise_level → 최종 두 폭 | 상위 재레이즈 축소 및 최종 cap |

모두 preflop / REASONING / JUDGMENT, 기존 authored heuristic, ACTIVE이며 RNG를 호출하지 않는다. 직접 consumer는 defend_thresholds, 이후 defend_action_likelihoods와 관찰자 range 모델이 소비한다. 별도의 4bet solver prior를 추가한 것이 아니므로 기존 SEMANTICALLY_OVERLOADED 판정은 유지한다. 함수 경계는 분리됐지만 공유 지식 문제는 미해결이다.

## 3차: range_read 소비 경계
