# 가상 대회 시계 설계 (초안)

목표: 히어로 핸드가 끝나면(결과·우승자·수거 모션 뒤) 바로 다음 핸드로 넘어간다.
다른 테이블은 실제 대회처럼 각자 속도로 진행하고, 계산은 히어로가 생각하는 동안
미리 해 둔다.

## 1. 사용자 결정 (2026-10-04)

| 항목 | 결정 |
|---|---|
| 속도 기준 | 온라인. 편차를 잰 뒤 조정 |
| 브레이크 | 온라인식 매시 55분에 5분. 히어로보다 뒤처진 테이블 편차가 크면 브레이크를 늘리는 방향 |
| 레벨 길이 | 온라인 자료를 따른다. 1·2번(속도·브레이크)을 바꾸면 레벨도 맞춰 바꾼다 |
| 핸드포핸드 | 머니 버블, 파이널 테이블 버블(마지막 두 테이블 → 한 테이블), 새틀라이트 좌석 버블 |
| 시간 | 가상 시간(같은 시드면 같은 대회). 실제 대기는 화면 연출에만 |

## 2. 근거 자료(온라인)

| 항목 | 자료 |
|---|---|
| 시간당 핸드 | 온라인 9인 풀링 60~80핸드/시간, 인원이 적으면 더 많다 |
| 레벨 길이 | PokerStars: Slow 15분, Regular 10분, Turbo 5분, Hyper 3분 |
| 브레이크 | PokerStars: 매시 55분에 5분, 전 테이블 동시 |

출처: upswingpoker.com(시간당 핸드), pokerstarsmi.com·PokerStars 자료 요약(레벨·브레이크).

### 형식별 레벨 길이(안)

지금 레벨당 핸드 수(hpl)는 이미 온라인 속도(시간당 약 70핸드)와 맞는다:
표준 12핸드 ≈ 10분, 터보 7 ≈ 6분, 하이퍼 4 ≈ 3.4분, 딥 18 ≈ 15분.

| 형식 | hpl | 자료 대응 | 레벨(분) |
|---|---|---|---|
| deep | 18 | Slow | 15 |
| standard | 12 | Regular | 10 |
| turbo | 7 | Turbo | 5 |
| hyper | 4 | Hyper | 3 |
| lowbuyin | 15 | 자료 없음 — hpl 비례 | 13 |
| main | 16 | 자료 없음 — hpl 비례 | 14 |
| highroller | 14 | 자료 없음 — hpl 비례 | 12 |
| satellite | 12 | Regular | 10 |
| bounty | 10 | 자료 없음 — hpl 비례 | 9 |

자료 없는 형식은 hpl × 60/70 을 반올림했다(판단 필요).

## 3. 핸드 한 개의 가상 시간

가정(모델): 기본 + 액션별(폴드 < 체크·콜 < 벳·레이즈) + 스트리트 전환 + 쇼다운.
모양만 가정하고 크기는 자료에 맞춘다 — 9인 핸드 평균이 3600/70 초가 되도록 배율을 정한다.
인원이 적으면 액션이 줄어 자동으로 빨라진다(자료와 같은 방향).

## 4. 진행 규칙

1. 모든 테이블이 같은 가상 시계를 쓴다. 테이블마다 자기 핸드 시간만큼 시계가 간다.
2. 블라인드 레벨은 가상 시계로 오른다(내가 빨리 폴드해도 레벨이 빨라지지 않는다).
3. 브레이크: 가상 55분이 되면 진행 중인 핸드까지 하고 쉰다. 모두 가상 정각에 다시 시작.
   미리 계산은 브레이크를 넘지 않는다.
4. 확정선: 히어로 테이블의 현재 가상 시각까지 확정, 그 뒤는 임시.
5. 이동 멈춤 지점: 임시 구간에서 탈락이 나면 —
   - 히어로 테이블에서 몇 명이 떨어지든 이동(해체·균등화)이 생기지 않으면 계속 계산;
   - 이동이 생길 수 있으면 모든 테이블이 그 시각에서 멈춘다. 히어로가 그 시각에 오면 이동을
     정하고(TDA 규칙 그대로) 다시 진행.
6. 이동이 생긴 테이블(사람이 빠지거나 들어온 곳)은 그 시각 이후 임시 결과를 버리고 다시 계산.
7. 핸드포핸드 지점(머니 버블, 파이널 테이블 버블, 좌석 버블)에 들어서면 멈춤 지점으로 보고
   그 구간은 모든 테이블이 한 핸드씩 같이 진행한다.
8. 앞서 가는 양 상한: 브레이크(최대 한 세션). 메모리 보호용으로 별도 상한을 둘 수 있다.

## 5. 브레이크 = 대기를 숨기는 자리

- 다른 테이블 계산이 히어로보다 늦으면 브레이크 화면 동안 따라잡는다.
- 화면: "휴식 5분" + 건너뛰기. 다른 테이블이 이미 끝났으면 바로 시작, 아니면 진행 표시.
- 편차가 크면 브레이크 길이(가상·표시)를 늘린다(사용자 결정 1·2).

## 6. 측정할 것(시뮬레이션 `tools/vclock_sim.py`)

- 세션(55분)마다 테이블별 핸드 수의 차이.
- 세션마다 다른 테이블 계산 시간(순차 / 테이블당 한 코어일 때 하한) 대 히어로 실제 시간.
- 필요한 브레이크 길이(히어로 속도·폰 배율별).

### 결과 (100명 표준, 140라운드, 시드 5·6)

| 항목 | 값 |
|---|---|
| 핸드 가상 시간 | 평균 약 49초, 중앙 45초, 상위 10% 76~79초. 9인 51초, 8인 48초, 7인 38초, 6인 27초 |
| 세션(55분)당 테이블별 핸드 수 | 시드 5: 62~70(평균 65.6, 표준편차 2.3) / 시드 6: 56~68(평균 62.8, 표준편차 3.6) |
| 가장 빠른·느린 테이블 차이 | 세션당 8~12핸드. 브레이크마다 0으로 맞춰진다 |
| 테이블 하나 세션 계산(서버) | 평균 약 30초, 최대 35초 |
| 다른 테이블 전체 세션 계산(서버, 순차) | 약 310~340초 |

폰 배율: 사용자 녹화에서 같은 라운드가 폰 약 40초, 서버 약 6초 → 약 6.7배(추정, 기기마다 다름).

세션당 추가 대기 = max(0, 다른 테이블 계산(폰) / 코어 수 − 히어로 실제 시간). 히어로 실제 시간 = 64핸드 × 핸드당 실제 초.
그림: `docs/beta/vclock_break_budget.png`.

| 히어로 핸드당 실제 시간 | 1코어(지금) | 2코어 | 4코어 |
|---|---|---|---|
| 15초 | 약 20분 | 약 2분 | 0 |
| 20초 | 약 14분 | 0 | 0 |
| 30초 | 약 4분 | 0 | 0 |
| 45초 | 0 | 0 | 0 |

해석: 지금처럼 한 코어로 다른 테이블을 돌리면 5분 브레이크로는 부족하다(히어로가 빠를수록).
테이블별로 여러 코어에 나눠 돌리면 5분 브레이크 안에 충분히 들어간다. 단, 이동 멈춤 지점에서
미리 계산이 쉬는 시간은 이 계산에 없다 — 구현 뒤 실제 대기로 다시 잰다.

## 7. 구현 상태 (2026-10-04, test)

- HERO 테이블: 실제 wall-clock을 초 단위로 사용한다. 레벨/55분 세션 경계도 초 단위다.
- 비-HERO 테이블: 각 Table에 `vclock_seconds`를 저장하고 120초 chunk로 세션 끝까지 계속 선계산한다.
- 화면 연출(액션 1.5초, HERO 호흡, 보드/결과)은 유지하지만 계산을 막지 않는다.
- 탈락 또는 hand-for-hand 진입은 barrier다. barrier 뒤 임시 결과는 확정하지 않는다.
- HERO 핸드 경계에서 barrier까지 결과를 반영한 뒤 실제 `_collect_busts()`/`_balance()`로 이동을 확정하고,
  이후 선계산은 폐기해 새 좌석 상태에서 다시 시작한다.
- 이동 때문에 멈춘 봇 테이블은 HERO 경계까지 기다린 것으로 시계를 맞춘다.
- 55분 경계를 HERO 핸드가 넘겨 끝내면 초과 wall-clock은 다음 세션으로 넘기지 않고 55:00에 고정한다.
  5분 브레이크 동안 뒤처진 계산이 계속되며, 끝나지 않으면 브레이크 이후에도 동기화 완료 전까지 재개하지 않는다.
- 현재 엔진 calibration probe: raw 평균 42.414초/핸드(n=29, seed=5150),
  70 hands/hour 목표에 대한 기본 `T2_VCLOCK_SCALE=1.2125`.
