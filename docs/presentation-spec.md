# 1인칭 테이블 연출 사양 (초안, 2026-10-26)

T2 테이블 화면을 1인칭 2.5D 로 바꾸는 사양이다. **설계 문서이고, 아직 구현하지 않았다.**
지금 UI 는 전면적으로 수정할 예정이다(사용자 결정). 이 문서의 숫자는 시안(PNG)으로만 맞춘 값이라,
기기 화면에서 보고 조정해야 한다.

- 시안: `docs/presentation/layout_fov55.png`
- 시안 생성 스크립트: `docs/presentation/mockup_render.py`. 실행 예: `HFOV=55 python3 mockup_render.py -2.5 1.0`.
  PIL 로 원근 투영을 직접 계산한다.

## 0.1 화면 방향 규칙

| | 세로 | 가로 |
|---|---|---|
| 로비 | 지금 로비(보류 중인 v2 개편 포함) | **가로 로비 새로 만든다**(시안 `docs/presentation/lobby_landscape.png`) |
| 테이블 | 지금 2D 테이블 그대로 | **이 문서의 1인칭 테이블만** |

**전환 방식**
- 폰을 돌리면 같은 화면의 다른 판으로 바뀐다. 게임 상태는 서버에서 오므로, 바뀌어도 진행이 끊기지 않게 한다.
- 화면 방향 고정을 풀어야 한다. 지금 안드로이드 앱이 세로로 고정돼 있다면 그 설정을 바꾼다.
- 두 판은 같은 서버 데이터와 같은 이벤트 변환(8장)을 쓰고, 그리는 쪽만 다르다.

**가로 로비 구성(시안)**
- 메뉴(로비, 대회, 내 기록, 설정): **화면 아래 가운데에 떠 있는 작은 창**(PiP 처럼 그림자와 반투명 배경)으로 둔다. **움직이지 않고 위치가 고정이다**(사용자 결정). 브랜드(♠T2)는 장면 왼쪽 위로 옮긴다.
- 왼쪽: 라운지 장면(공항) 전체. 라운지 캐릭터가 돌아다니는 자리다.
- **추천 대회 = 위에서 내려오는 알림**(아이폰 알림처럼, 사용자 결정):
  - 크기: 약 340×58. 왼쪽에 작은 그림, 가운데 두 줄(상태·남은 시간 / 이름·바이인·인원), 오른쪽에 `참가 신청`.
  - 등장: 로비에 들어오면 화면 위 가운데로 미끄러져 내려온다(0.35초, 살짝 튕김). 떠 있는 동안 자동으로 사라지지 않는다.
  - 닫기: **옆으로 밀면 그 방향으로 날아간다.** 너비의 30% 이상 밀거나 빠르게 튕기면 닫히고, 덜 밀면 제자리로 돌아온다.
  - 누르면 대회 정보가 열리고, `참가 신청` 은 바로 신청한다.
  - 다시 보이는 조건: 닫은 대회는 다시 띄우지 않는다. 다만 상태가 바뀌면(추가 등록 마감 10분 전, 곧 시작) 한 번 더 띄운다.
- 오른쪽: 보유 칩, 프로필, 예정된 대회 목록(종류 탭과 참가 신청·취소 버튼).
- 색: v2 와 같다. 밤은 남색과 금색, 낮은 아이보리와 금색이다.

## 0.2 그림체 규칙 (UI 를 캐릭터 그림에 맞춘다 — 사용자 승인 2026-10-26, A안)

로비, 1인칭 테이블의 버튼·말풍선·명패·가장자리 표시, 알림이 모두 이 규칙을 따른다.

| 항목 | 규칙 |
|---|---|
| 외곽선 | 진한 갈색 `#3a2414`(밤 화면 판은 `#120f1c`), 2~3px. 캐릭터 외곽선과 같은 느낌 |
| 입체감 | 아래로 딱 붙은 그림자 `0 3px 0 외곽선색`(스티커처럼 도톰하게). 흐린 그림자는 떠 있는 창(알림, 메뉴)에만 더한다 |
| 글꼴 | 제목·숫자·버튼은 **주아(Jua)**, 작은 글씨는 **고운돋움(Gowun Dodum)**. 둘 다 OFL 이라 앱에 넣는다 |
| 색 | 밤: 남색 판 `#2b3150` + 크림 글씨 + 호박색 `#f2b84b`. 낮: 크림 종이 `#fbf1dc` + 갈색 글씨 + 호박색 |
| 질감 | 판에 아주 옅은 점무늬(종이 느낌) |
| 아이콘 | 외곽선 굵기를 같게 하고 안을 채운 단순한 모양 |
| 주 버튼 | 호박색 그라데이션, 외곽선, 아래 그림자 |
| 대회 목록·알림 | **캐릭터 그림을 넣지 않는다**(사용자 결정). 알림은 트로피 아이콘 |
| 인게임 | **같은 규칙으로 통일**(사용자 결정). 시안 `docs/presentation/ingame_landscape.png` |
| 쓰지 않는 것 | 시스템 이모지, 유리처럼 비치는 효과만으로 된 판, 반실사 사진 |



단위는 m 이다. 테이블 중심이 원점이고, x 는 오른쪽, z 는 내 쪽(아래), y 는 위 방향이다.

| 값 | 크기 |
|---|---|
| 테이블 펠트 반축 | A=1.55, B=0.95 (타원) |
| 테이블 높이 | 0.75 |
| 레일 | 펠트 바깥으로 10~13% |
| 딜러 | 각도 −90°(맨 위, 먼 쪽), 반경 배율 1.30 |
| 좌석 k(1~9) | 각도 = −60° + 37.5°×(k−1), 반경 배율 1.28 |
| 좌석 위치 계산 | (A·s·cosθ, B·s·sinθ) |

결과적으로 5번이 딜러 맞은편이다. 1번과 9번이 딜러 양옆이고, 좌우가 대칭이다.

## 1.1 빈자리와 재배치 (사용자 결정 2026-10-26)

- 기본: 빈 의자를 그대로 둔다. 실제 테이블처럼 자연스러운 상태로 본다.
- 인원이 적어 휑하면 **화면에서만** 자리를 다시 배치한다. 서버 좌석 번호는 그대로 두고, 화면 좌석으로 바꾸는 표만 쓴다.

| 남은 인원 | 화면 자리 |
|---|---|
| 4명 | 두 칸에 한 명. 예: 2·4·6·8번 (좌우 대칭) |
| 2명 | 테이블 양 끝, **3·7번** (사용자 확인) |

- 4명 예시 번호와, 3명·5~6명일 때 재배치할지는 기기에서 보고 정한다.
- 재배치는 핸드와 핸드 사이에만 한다. 내 화면 자리가 바뀌면 카메라 프리셋도 그 자리 것으로 바뀐다.

**서버 좌석 번호와의 관계**
- 지금 화면은 내 자리를 늘 하단 중앙으로 **회전**해서 그린다(`ui/web/app.js` `slotPos`).
- 새 화면에서는 회전하지 않고, 서버 좌석 번호를 그대로 물리 좌석으로 쓴다.
- 그래야 자리마다 구도가 달라진다.

## 2. 카메라 프리셋 (좌석별)

구도는 5종류다. 6~9번은 4~1번을 좌우로 뒤집은 것이다.

| 내 자리 | 화면 안 상대 (시안 기준) | 비고 |
|---|---|---|
| 5 | 1·9번과 딜러 | 상대 2명. 테이블이 넓게 보인다 |
| 4 / 6 | 2명과 딜러 | |
| 3 / 7 | 4명 | |
| 2 / 8 | 4명 | |
| 1 / 9 | 3명 | 딜러는 화면 밖, 바로 옆 |

공통값은 다음과 같다.
- 위치: 좌석 위치(반경 1.28), 높이 1.0
- 바라보는 점: 테이블 중심(0, 0.75, 0)
- 추가 내려보기: −2.5°
- 가로 시야: 55°
- 기준 해상도: 844×390(가로)

**주의할 점**
- 내려보는 각도의 여유가 좁다. 1~2°만 올려도 상대 얼굴이 화면에 들어오고, 더 내리면 상대 몸통이 화면 위 끝에서 잘린다.
- 그래서 각도는 **좌석마다 하나씩 데이터로 둔다.** 기기에서 보고 맞춘다.
- 시야를 60~65°로 넓히면 3·2번 자리에서 상대가 5명 보인다. 최대 4명을 지키려면 55°가 상한이다.

데이터 형태(예시):
```json
{ "camera_presets": {
    "5": {"height": 1.0, "hfov": 55, "pitch_extra": -2.5},
    "4": {"height": 1.0, "hfov": 55, "pitch_extra": -2.5},
    "3": {"height": 1.0, "hfov": 55, "pitch_extra": -2.5},
    "2": {"height": 1.0, "hfov": 55, "pitch_extra": -2.5},
    "1": {"height": 1.0, "hfov": 55, "pitch_extra": -2.5} },
  "mirror": {"6": "4", "7": "3", "8": "2", "9": "1"} }
```

화면 비율이 기준(844×390)과 다르면 가로 시야 55°를 유지하고, 세로 시야가 따라 바뀌게 한다.

## 4. 상대 표시

**몸통**
- 각 상대는 좌석 위치에 세운 판(빌보드)이다.
- 테이블 높이에서 어깨(약 1.12m)까지 보이고, 얼굴은 화면 밖이다.
- 지금 초상화는 머리와 깃만 있다. 그래서 캐릭터마다 **상반신(옷, 팔) 그림이 새로 필요하다**(9장에 목록). 표정 그림은 필요 없다.

**대기 모션**
- 숨쉬기: 세로 크기 1.00 ↔ 1.01, 주기 3~4초, 캐릭터마다 위상을 무작위로 준다.
- 크게 움직이지 않는다. 차분한 구도를 유지한다.

**누구인지 알리기**
얼굴이 없으므로 다음 세 가지로 구분한다.
1. 옷 색깔(캐릭터 고유색)
2. 테이블 위 **명패**: 상대 앞 레일 쪽에 이름 `T-########` 과 스택을 둔다. 스택은 칩/BB 전환을 따른다.
3. 포지션 표시(BTN·SB·BB)는 명패 옆 작은 표식으로 둔다.

## 5. 말풍선 위치 규칙 (사용자 결정 2026-10-26)

말풍선은 **액션할 때만** 뜨고(1.2~1.6초 뒤 흐려짐), 늘 떠 있는 가장자리 목록은 두지 않는다.
위치는 그 상대가 내 화면에 얼마나 보이느냐로 정한다.

| 그 상대가 화면에 | 말풍선 위치 | 꼬리 |
|---|---|---|
| **몸통의 3/4 이상 보임** | 얼굴 쪽(몸통 위 끝, 3D 화면 위쪽) | **아래로**(그 사람을 가리킴) |
| 3/4 미만(가장자리에 잘림) 또는 안 보임 | **화면 좌우 바깥 가장자리**. 그 좌석이 카메라 왼쪽이면 왼쪽, 오른쪽이면 오른쪽 | **바깥쪽으로**(화면 밖 그 사람 방향) |

- "3/4 이상" 은 몸통 빌보드의 가로 폭 중 화면 안에 들어온 비율로 잰다.
- 가장자리 말풍선의 세로 위치는 테이블 둘레 순서를 따른다. 내 쪽에 가까운 자리일수록 아래로 둔다. 동시에 여러 개가 뜨면 겹치지 않게 쌓는다.
- 내용: 작은 글씨로 포지션, 큰 글씨로 액션(예: `UTG+1 폴드`, `CO 레이즈 2.5bb`). 차례가 왔는데 아직 액션 전이면 `생각 중…` 을 띄울 수 있다(선택).
- 카메라는 움직이지 않는다.

## 5.1 채팅창 (아래 왼쪽, 사용자 결정 2026-10-26)

- **반투명**(사용자 결정): 기록창과 스티커 줄 모두 어두운 반투명 바탕(불투명도 약 40%, 살짝 흐림)에 옅은 외곽선. 뒤 테이블이 비쳐 보인다. 글씨는 아래 그림자로 읽히게 한다.
- **글은 쓸 수 없고, 이모티콘(스티커)만 보낸다.** 아래 줄에 스티커 5개: 웃음, 크게 웃음, 울음, 화남, GG.
- 같은 줄에 **칩 셔플 버튼**을 둔다(사용자 결정). 누르면 내 손이 셔플을 한 번 한다. 스티커와 모양을 구분한다(손 아이콘 등).
  - 상대에게도 보인다. 그 상대 화면에서 내가 화면 안이면 손 동작, 화면 밖이면 5장 규칙 위치에 짧은 말풍선(`셔플`)으로 보인다.
  - 셔플 중에 액션 버튼을 누르면 셔플을 바로 끊고 액션 동작으로 넘어간다.
  - 남발을 막는 간격을 스티커와 함께 둔다.
  - 그림체 규칙을 따른 전용 그림이다. 시스템 이모지는 쓰지 않는다.
- 위쪽 기록창에는 두 종류가 섞여 올라온다. 둘은 **모양으로 구분한다.**

| 종류 | 모양 |
|---|---|
| 액션 해설 | 왼쪽에 세로 줄, 작은 회색 글씨. `포지션 이름 액션`, 액션만 호박색 |
| 채팅(스티커) | 보낸 사람 이름(나는 호박색, 남은 하늘색)과 크림색 칸 안의 스티커 |

- 새 줄은 아래에 붙고, 오래된 줄은 위로 밀리며 흐려진다. 위로 끌면 지난 기록을 본다.
- 스티커는 테이블 위에 띄우지 않고 채팅창에만 올린다. 말풍선은 액션 전용이다.
- 제안: 스티커 남발을 막는 간격(예: 3초에 1개). 봇이 가끔 스티커를 보낼지는 따로 정한다.

카메라를 고정한 대신 **말풍선, 손 동작, 소리**로 액션감을 준다. 이모티콘(스티커)은 채팅창에서만 쓴다(5.1).

| 액션 | 말풍선 | 상대 손(화면 안일 때) | 소리 |
|---|---|---|---|
| 체크 | "체크" | 테이블을 두 번 두드림 | 톡톡 |
| 콜 | "콜 2.5bb" | 칩 더미를 앞으로 밂 | 칩 |
| 벳·레이즈 | "레이즈 7.5bb" | 칩을 크게 밂 | 칩 여러 개 |
| 폴드 | "폴드" | 카드를 앞으로 던지듯 내려놓음 | 카드 슥 |
| 올인 | "올인"(강조 테두리) | 양손으로 전부 밂 | 칩 쏟아짐 |
| 쇼다운 | 패 이름 | 카드를 뒤집음. **화면 밖 상대는 가장자리 말풍선 안에 카드 2장을 작게** 보여 준다 | 카드 뒤집기 |
| 칩 셔플(버튼) | 화면 밖일 때만 "셔플" | 셔플 | 칩 짤각 |
| 승리 | "+12.4bb" | 팟을 끌어옴 | 칩 모음 |

- 말풍선 위치와 꼬리는 5장 규칙을 따른다.
- 1.2~1.6초 보여 준 뒤 흐려진다. 지난 액션은 채팅창 해설에 남는다.
- 금액은 칩/BB 전환 설정을 따른다.
- **스티커는 시스템 이모지를 쓰지 않는다.** 사용자가 이모지가 싸 보인다고 판단해 제거한 적이 있다(브레이크 배너). 그림체에 맞춘 전용 스티커 그림을 쓴다. 그림이 없는 동안은 단색 도형으로 자리만 잡는다.
- 같은 자리에 새 액션이 오면 이전 말풍선을 바로 바꾼다.

## 7. 내 손 (아래 가운데)

| 상황 | 동작 |
|---|---|
| 카드 받기 | 딜러 쪽에서 미끄러져 온 카드를 끌어옴 |
| 카드 확인 | 두 손으로 모서리를 들춰봄(스퀴즈). 누르고 있는 동안만 보인다 |
| 체크 | 테이블 톡톡 |
| 콜·벳·레이즈 | 칩 더미를 앞으로 밂. 크기에 따라 칩 수가 다르다 |
| 폴드 | 카드를 앞으로 내려놓음 |
| 올인 | 칩이 많으면 양손, 적으면 오른손으로 밂 |
| 대기 중 | 동작 없음. **칩 셔플은 버튼으로만**(5.1) |

**손이 보이는 규칙 (사용자 결정 2026-10-26)**
- 평소에는 **두 손 모두 화면 밖**에 둔다. 동작할 때만 아래에서 들어오고, 끝나면 다시 내려가 사라진다.
- 동작은 **오른손 위주**다. 카드 받기·정리, 프로텍터, 체크, 콜·벳·레이즈, 폴드, 칩 셔플은 오른손만 쓴다.
- **두 손이 보이는 경우는 둘뿐이다.**
  1. 카드 확인(들춰보기): 두 손으로 감싸 들춘다.
  2. 올인 중 **칩이 많을 때**: 두 손으로 감싸 민다. 칩이 적은 올인은 오른손만 쓴다. "많음" 기준은 12장의 칩 개수 구간이 정해지면 그에 맞춘다.
- 왼손만 쓰는 동작은 없다.

손 동작은 **버튼을 누른 즉시** 시작한다. 서버 응답을 기다리지 않는다. 서버가 거절하면 되돌린다.

### 7.1 손 동작 시제품 (2026-10-26)

`ui/web/proto/motions.html` 에 Three.js(0.160.0, MIT, `ui/web/vendor/` 에 넣음, 외부 CDN 없음)로 만든 시제품이 있다.
게임 화면과 분리된 페이지라 게임 동작에는 영향이 없다. 손은 임시 상자(파란 손, 남색 소매)다.
열기: 로그인한 상태로 `http://127.0.0.1:8080/proto/motions.html`. 가로 화면 전용이다.

| 동작 | 구현 |
|---|---|
| 새 카드 | 딜러 쪽에서 두 장이 돌며 미끄러져 와 비뚤게 놓인다 |
| **카드 정리** | 왼손이 카드 왼쪽 옆으로 와서 두 장을 가지런히 모으고(살짝 겹침), 톡 눌렀다 뗀다 |
| 들춰보기 | 왼손으로 가까운 모서리를 든다(먼 쪽 모서리가 경첩). 카메라가 고정이라 실제보다 크게(약 65°) 들어 앞면이 보이게 했다. 프로텍터가 있으면 먼 쪽으로 밀렸다가 돌아온다 |
| 앞/뒤 | 두 장을 차례로 뒤집는다(시제품 확인용) |
| **카드 프로텍터** | 금색 원판(♠T2). 왼손이 옆에서 집어 카드 위에 올리고 살짝 돌린다. 다시 누르면 제자리로 치운다 |
| 폴드 | 프로텍터가 있으면 먼저 치우고, 두 장을 앞으로 밀어 낸 뒤 사라진다 |
| **칩 셔플** | 두 더미(빨강·남색)를 나란히 두고 안쪽을 눌러 서로 기대게 한 뒤, 아래부터 번갈아 한 장씩 가운데로 끼워 한 더미로 만든다. 손가락으로 눌러 가지런히 하고, 다시 둘로 나눈다(색별) |
| 대기 셔플 | 켜 두면 아무 동작이 없을 때 2.5~6초마다 셔플한다. **확정 사양에서는 빼고 버튼으로 옮긴다**(5.1) |
| **칩 내밀기** | 오른손 손끝을 금색 더미 위쪽 칩 4개에 대고 베팅 선 앞으로 밀어 놓는다 |
| 올인 | 두 손으로 앞의 칩을 모두 감싸 밀어 낸다 |

- 화면 오른쪽 위 `1인칭 / 가까이`: 1인칭은 사양 2장의 카메라(가슴 높이, 시야 55°), 가까이는 손 동작 확인용이다.
- `?speed=0.3` 을 붙이면 느리게, `?shot=manual` 이면 시간을 손으로 넘긴다(스크린샷용 `__t2motion.step(ms)`).
- **시제품과 사양이 다른 점**: 시제품은 카드 정리·들춰보기·프로텍터를 왼손으로 하고 손이 늘 보인다. 사양은 평소 손을 숨기고, 들춰보기는 두 손, 나머지는 오른손이다. 시제품 수정 필요.
- 정해 줄 것: 프로텍터 모양(지금은 금색 ♠T2 원판, 캐릭터별로 바꿀지), 들춰보기 각도. 칩 내밀기 개수는 12장 참고.

## 8. 구조 (로직과 연출 분리)

```
서버 상태(v) ──▶ 이벤트 변환 ──▶ 연출 큐 ──▶ 3D 장면(손·칩·카드)
                                        └──▶ 화면 위 표시(DOM: 버튼, 대회 정보, 가장자리 표시, 말풍선)
```

**이벤트 변환**
- 기존 `v.log` 의 새 항목(street, seat, action, amount)을 이벤트로 바꾼다. 예: `{type:'raise', seat, amount, street}`.
- 지금 코드의 원칙을 그대로 따른다: 스냅샷으로 따라잡을 때는 지나간 액션을 **재생하지 않고** 결과 상태로 바로 맞춘다(`app.js` 256행 주석).

**제스처 메시지**
- 칩 셔플 버튼은 게임 액션이 아니므로 `v.log` 에 넣지 않는다. 스티커와 같은 길로 서버에 보내고 같은 테이블 사람에게 돌린다. 예: `{type:'gesture', seat, name:'shuffle'}`.
- 받은 쪽은 그 자리가 화면 안이면 손 동작, 밖이면 말풍선으로 그린다.

**연출 큐**
- 이벤트를 차례대로 재생한다.
- 동작마다 길이를 데이터로 둔다(`presentation_timing.json`). 타이밍 조정은 이 파일만 바꾼다.
- 서버의 시간 규칙(`timing.py`, 딜 7.5초, 보드 2초 등)보다 연출이 길어지면 안 된다. 연출이 밀리면 줄인다.

**손 교체 지점**
- `HandRig.play(name, params)` 하나로 부른다.
- 처음에는 색 상자로 구현하고, 나중에 2D 그림이나 3D 모델로 바꾼다. 바꿔도 로직은 그대로 둔다.

**기술**
- Three.js 를 정확한 버전으로 고정해 실행 폴더에 넣는다. 외부 CDN 을 쓰지 않는다.
- 안드로이드 웹뷰(S23)에서 60fps 를 목표로 한다.
- 텍스처는 2048 이하, 그림자는 가짜 그림자(바닥 판)로 처리한다.

## 12. 칩 단위와 색 (사용자 방향 2026-10-26, 시스템 수정 필요)

- 칩 단위별로 색을 달리해서, 큰 금액도 적은 칩 수로 간결하게 보여 준다. 내미는 칩 수가 금액에 따라 끝없이 늘지 않게 한다.
- 이를 위해 **최소 칩 단위 제한**을 둔다. 지금 게임에는 없다.
- 이건 연출만의 일이 아니라 **게임 규칙 수정**이다. 정할 것:
  - 베팅·스택 금액을 최소 칩 단위의 배수로 맞출지, 맞춘다면 남는 금액 처리
  - 블라인드가 오를 때 작은 칩을 큰 칩으로 바꾸는 방식(정리 시점, 남는 칩 처리)
  - 봇 판단(`gto*.py`, `bot.py`)과 ICM 계산에 미치는 영향
- 별도 작업으로 설계한 뒤 사용자 승인 후 구현한다. 그전까지 연출은 금액을 그대로 쓰고, 칩 수만 구간별 상한(예: 1~8개)으로 묶는다.
