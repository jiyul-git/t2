# 오픈 사이즈 근사 실험 — 40bb, BB 디펜스 vs BTN/CO, 3.0 held-out (2026-10-30)

세션 01JQGB…, 브랜치 `claude/size_approx_20261030`. T2 연결 없음, db_promotion 금지. 칩 EV, 9-max, 앤티 1bb, 대칭 스택 40bb.

## 1. 설정
- 앵커: 2.0 오픈 = `p40_flat_btn/co_vs_bb`, 2.5 오픈 = `p40_flat_btn/co_vs_bb_o25` (test3 `data/gto_records`, sha256은 MANIFEST와 일치).
- held-out 3.0: 새 부모 `cfg_p40_o30` (cfg_p40_v1과 동일, UTG..BTN 오픈 3.0 고정, SB 3.5). 175 iter, exact gap **0.00991 bb**
  (`parent_p40_o30_convergence.json`, dump `transfer/p40_o30_dump.jsonl.gz`). RFI: BTN 35.9 %, CO 27.8 % (2.0 부모 41.1 / 32.2).
  스팟 `p40_flat_btn_vs_bb_o30`(3 step 캡, step 1-2 평균, unstable 228 combos), `p40_flat_co_vs_bb_o30`(step 2 수렴). quick 기준, max 3 steps.
- 비교 대상 = BB 루트 노드, 169 클래스, 액션 4그룹(fold / call / 3-bet 두 사이즈 합 / jam). 오차 = 클래스별 TV 거리 ½Σ|Δ|, 콤보 가중.
- 가격축 x = BB 필요 승률 = (open−1)/(pot+call), pot은 블라인드+앤티 포함: 2.0 → 0.182, 2.5 → 0.231, 3.0 → 0.267.
- 도구: `tools/gto_spot/size_approx_fit.py`(클래스별 선형), `size_approx_threshold.py`(문턱형). 결과 JSON: `data/gto_spot/size_approx/`.

## 2. 출처(provenance) 주의
- 2.0 기록 = 2.0 고정 부모(gap 0.0086, 150 iter). 2.5 기록 = {2.0, 2.5} 부모(gap 0.0116, 400 iter)의 2.5 가지. 3.0 = 3.0 고정 부모.
  다만 {2.0,2.5} 부모에서 BTN은 2.5만 사실상 사용(39.1 % vs 2.0 0.2 %), CO도 29.9 % vs 0.7 % → 2.5 레인지 차이는 작다.
- 상태: BTN 2.0(수렴), BTN 2.5(수렴), BTN 3.0(캡·평균, 불안정 228 combos); CO 2.0(수렴), CO 2.5(캡·평균, 불안정 216), CO 3.0(수렴).
- 3.0은 앵커 바깥 → 이 시험은 **외삽** 시험이다. 앵커 사이(예: 2.25) 보간 정확도는 시험하지 않았다.

- **A/B가 클램프(C)와 같은 이유**: 3.0에서 새로 폴드하는 약한 오프수트(BTN: Q8o, K8o, J4o, 84o, 92s, 73o…; CO: A2o, Q6o, K3o, T9o, 54o…)는
  2.0과 2.5에서 둘 다 콜 ~100 %였다. 두 점이 같으면 직선도 평평하다 → 클래스별 선형은 "새로 경계를 넘는 클래스"를 원리상 못 잡는다.
  2.0→2.5에 이미 넘어간 클래스는 1에서 잘려 더 갈 데가 없다. 그래서 전체 fold가 2.5 값에 머문다.
- 경계 플래그(우세 액션이 2.0/2.5/3.0 사이에 바뀌거나 방향이 꺾임): BTN 50 클래스(498 combos), CO 55(524). 오차의 거의 전부가 여기서 나온다.
- D/E(문턱형) = 앵커 데이터만 사용: 전체 fold 비율을 두 앵커로 직선 외삽 → 2.5 기록의 EV(최선 계속)−EV(fold) 순으로 약한 클래스부터 폴드,
  계속하는 클래스는 2.5의 계속 믹스 유지. 오차가 절반 이하로 줄지만 최대 오차 1.0 클래스가 여전히 있다(순위가 사이즈 따라 바뀜, 3-bet/jam 블러프 교체 등).
- **가격축은 bb축보다 낫지 않았다.** fold는 가격에 대해 가속(0.182→0.231: +11~16 pp, 0.231→0.267: +17 pp)하므로
  가격 직선은 부족하게 외삽한다(BTN 28.7 vs 37.0, CO 40.0 vs 44.1). bb 직선이 더 가깝다(31.7, 44.2). 두 스팟뿐이므로 일반화는 금지.

## 4. 판정
**설계안(클래스별 가격축 선형, 앵커 2개)은 작동하지 않는다** — 2.5를 그대로 쓰는 것(클램프)보다 낫지 않다(평균 TV 0.18–0.22, 최대 1.0, fold 7–14 pp 부족).
문턱형은 개선(평균 TV 0.06–0.13)되지만 외삽으로는 여전히 fold가 5–8 pp(가격축) 빗나가고 클래스 단위 1.0 오류가 남는다.
→ 결론: **앵커 3개가 필요**(대상 사이즈를 양쪽에서 감싸서 외삽이 아니라 보간), 그리고 클래스별 선형 대신 **문턱(경계) 모델**.

## 5. T2 사용 제안 (연결은 하지 않음)
1. 스택 버킷별로 계산된 오픈 사이즈 앵커(40bb는 이제 2.0 / 2.5 / 3.0)를 보관. 실제 오픈 사이즈로 조회.
2. 앵커 사이: 이웃 두 앵커로 전체 fold 비율을 보간 → 아래쪽 앵커의 EV 마진 순위로 폴드 경계 이동, 계속 믹스는 가까운 앵커 것.
3. 앵커 바깥: 클램프(가장 가까운 앵커 그대로). 외삽 금지.
4. 스택 축은 지금처럼 버킷 별도 계산 + 보간(가격 변환 없음). ICM·사람 습관은 별도 레이어.
5. 쓰기 전에 보간 자체를 검증할 것: 40bb에서 2.25 또는 2.75 하나를 더 계산해 2.0/2.5/3.0으로 예측·비교(오늘 절차와 동일).
