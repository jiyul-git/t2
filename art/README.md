### `cutouts/tiger_walk_b/`

- `left_<행><열>.png` — b1을 2배로 키운 뒤(Real-ESRGAN anime) 빈 줄 기준으로 16칸으로 자름. 흰 배경, 바닥 그림자, 팔과 몸 사이 흰 틈은 투명. `left_33`은 Gemini 별 워터마크가 가슴에 남아 쓰지 않음.
- **`loop/left_0`~`7`, `loop/right_0`~`7` — 실제로 쓸 걷기 8프레임.** Gemini가 칸마다 얼굴·후드를 조금씩 다르게 그려서 칸을 그대로 이어 붙이면 얼굴이 부풀었다 줄고 `T2`가 깨졌다 붙는다. 그래서 윗몸(머리·후드·당기는 손·꼬리·손잡이·캐리어)은 `left_10` 한 장으로 고정하고, 후드 밑단 아래에서 `left_10` 위에 그은 경계선(`tools/lockbody.py`의 `EDGE`) 왼쪽, 즉 바지·주머니·발만 프레임마다 바꿨다. 경계선 오른쪽(손·손잡이·꼬리·캐리어)은 늘 같은 그림이라 깨지지 않는다. 다리 순서는 발을 재서 고른 한 걸음: `22 → 30 → 03 → 10 → 12 → 21` (뒷발 차고 들림 → 지나감 → 앞으로 나와 닿기 → 디딘 발이 뒤로 밀림). 양쪽 다리가 똑같이 생겨서, 디딘 발이 늘 뒤로만 가면 한 걸음 반복이 왼발·오른발 교대로 보인다. 제미나이는 반대발 자세를 끝내 못 그렸다(항상 화면 앞쪽 다리를 앞으로 냄). 발이 크게 건너뛰던 `03 → 10` 사이에는 손으로 만든 사이 칸을 넣었다(`tools/stride_tween.py`: `10`에서 두 다리를 따로 떼어 앞발은 30px 뒤로·10px 들고, 뒷발은 40px 앞으로 옮긴 뒤 앞다리를 위에 겹침). 그래서 한 걸음은 7칸. 호랑이가 비스듬히(3/4) 서 있어 화면 앞쪽 다리만 앞으로 뻗는 그림이라, 같은 걸음을 반복하면 옆으로 발차기하듯 보였다. 그래서 두 번째 걸음은 같은 7칸의 다리 역할을 바꿔 만든다(`tools/swap_legs.py`: 앞으로 나온 다리는 화면 안쪽 다리로 조금 위·작게·어둡게 뒤에, 뒤로 간 다리는 앞쪽 다리로 조금 아래에 위로 겹침. 두 발이 몸 아래 모인 칸은 그대로). 루프는 14칸. 밑단을 맞춘 뒤 발 위치 차이로 몸이 살짝 오르내린다.
- `loop/right_*` — `loop/left_*`를 좌우로 뒤집고 금색 `T2` 글자만 다시 뒤집어 바르게 읽히게 함.
- `walk_left.gif`, `walk_right.gif` — 위 8프레임 확인용 움직임.

도구: `tools/cut_sheet.py SHEET OUTDIR [행 열]`(칸 자르기), `tools/lockbody.py DIR BASE OUTDIR f1,f2,…`(윗몸 고정 + 다리 교체), `tools/mirror_logo.py IN OUT`(글자 유지 좌우 반전), `tools/stride_tween.py`(다리를 떼어 옮겨 사이 칸 만들기), `tools/swap_legs.py`(반대발 걸음 만들기), `tools/inkfix.py`(다리 윤곽 마감·흰 테두리 제거), `tools/build_tiger_walker.py`(위 과정을 한 번에 돌려 장면용 파일까지 만듦).

## 토끼·거북이 걷기 시트 (`sources/rabbit_walk_sheet_4x4_gemini.webp`, `sources/turtle_walk_sheet_4x4_gemini.webp`)

둘 다 4×4, 흰 배경. 칸 이름은 `cut_sheet.py`가 자른 `f_<행><열>`. 도구는 `tools/build_walker.py` 하나로, 캐릭터마다 설정(시트, 기준 칸, 치마·재킷 밑단 선, 루프 순서, 크기, 걸음)만 다르다. 실행하면 `ui/web/lounge/assets/chars/<이름>_walker/{atlas.webp, manifest.json}`을 호랑이와 같은 형식으로 만든다(`walk_r` = 그린 그대로, `walk_l` = 좌우 반전. 장면에서는 `pass: "r"`이라 `walk_l`은 쓰이지 않는다).

```
python3 art/tools/build_walker.py                    # 둘 다 다시 만들기
python3 art/tools/build_walker.py rabbit --measure   # 칸마다 발 위치 재기
python3 art/tools/build_walker.py turtle --dump DIR  # 루프 프레임을 PNG로도 저장
```

**깜빡임 막기.** 호랑이와 같은 방식: 윗몸 전체(머리·귀·리본·코트/재킷·두 팔·폰/카드·캐리어/배낭)는 기준 칸 한 장으로 고정하고, 치마·재킷 밑단 아래 다리만 프레임마다 바꾼다. 처음엔 머리만 고정하고 팔·캐리어는 칸마다 두려 했지만, 머리 기준으로 칸을 맞춰 보니 몸통·캐리어가 칸마다 5~10px씩 어긋나고 치마 길이도 달라서 머리만 고정하면 몸과 캐리어가 떨렸다. 그래서 윗몸 전체를 고정했다. 각 칸은 기준 칸의 몸통(목도리~밑단)에 크기·위치를 맞춘 뒤(템플릿 매칭, 배율 0.9~1.12) 밑단 아래에서 밑단에 닿는 조각만 다리로 가져온다(그 칸의 캐리어·부스러기는 버림). 다리 윤곽은 `inkfix.reink`로 다시 긋고, 밑단 바로 아래에서 치마 밖으로 삐져나온 부분은 지운다. 기준 칸의 다리는 흐린 가장자리까지 모두 지운다(겹쳐 보이는 유령 다리 방지). 시트의 흰 테두리는 `defringe`로 선 색으로 바꾼다.

**사이 칸.** Gemini 칸은 거의 모두 "디딤"(앞발 뒤꿈치, 뒷발 앞꿈치) 자세라 칸만으로는 걸음이 안 된다. 그래서 칸의 두 다리를 다리 사이 틈에서 나눠, 각 다리를 발 쪽으로 갈수록 더 많이 밀고(밑단에서는 0) 필요하면 들어 올려 사이 칸을 만든다(`stride_tween.py`와 같은 방식). 루프 항목 `(칸, 앞발 dx, 뒷발 dx, 앞발 들기, 뒷발 들기)`.

### 토끼

| 칸 | 판정 |
|---|---|
| `f_00`, `f_02` | 폰을 귀에 대고 캐리어가 반대쪽 — 방향이 달라 **제외** |
| `f_10` | 폰을 귀에 댐 — **제외** |
| `f_12`, `f_22` | 폰 없이 빈손 — 윗몸은 안 쓰므로 다리만 쓸 수 있지만 쓰지 않음 |
| `f_03` | **기준 칸** (리본 있음, 눈 뜸, 웃는 얼굴) |
| `f_33`, `f_11`, `f_13` | 디딤 자세 다리 (발 간격 106 / 94 / 81px) |
| `f_01` | 두 발이 몸 아래로 모인 자세 — 지나가는 자세의 바탕 |
| 나머지 (`f_20`~`f_32`) | 다리가 `f_03`·`f_13`과 거의 같아 쓰지 않음. `f_21`~`f_33`은 리본도 없음 |

루프(한 걸음 8칸, 10fps): `33 → 11 → 13 → 01 → 01 → 01 → 11 → 33`. 디딘 발의 바닥 위치(기준 칸 px)가 `244 → 230 → 218 → 207 → 191 → 178 → 166 → 151 → (다음 걸음 138)`으로 프레임마다 약 13px씩 뒤로만 가고, 든 발은 `138 → 153 → 172 → …` 앞으로 나와 다음 칸 0에서 디딘다. 0~3칸은 앞(밝은) 다리가 디딘 발이고, 발이 모이는 3→4칸에서 역할이 바뀐다(호랑이처럼 한 걸음을 되풀이해 왼발·오른발로 보이게). 걸음 `advance` 16 = 13.25px × 장면 배율. 크기: 귀 끝~발바닥 470 장면 px(머리 끝~발은 호랑이와 비슷, 귀만큼 더 큼).

### 거북이

시트가 작아(칸 약 150×170px) 2배 LANCZOS + 약한 언샤프로 키운 뒤 자른다(오프라인이라 AI 업스케일 없음). 휴대폰 화면 크기에서는 호랑이와 비교해 흐려 보이지 않는다.

| 칸 | 판정 |
|---|---|
| `f_33` | 카드 옆에 Gemini 별 워터마크 — **제외** |
| `f_11` | **기준 칸**, 그리고 모든 프레임의 다리 |
| 나머지 | 모두 오른쪽, 아주 고르게 그려짐. 하지만 다리가 거의 같은 디딤 자세(발 위치 차이 ±5px)이고 그 차이도 걸음 순서로 이어지지 않아(두 발이 함께 앞으로 가는 칸이 섞임) 쓰지 않음. `f_03`, `f_31`, `f_32`는 다리가 모인 자세지만 다리를 크게 옮기면 모양이 깨져 제외 |

다리가 짧고 엉덩이가 넓어 두 발이 서로 엇갈리지 않고 각자 엉덩이 아래에서 앞뒤로 움직이는 종종걸음으로 만들었다. 루프(8칸): `f_11` 다리를 발 쪽에서 밀어 앞발 `104 → 99 → 94 → 89 → 84`(0~4칸 디딤, 원래 시트 px), 그동안 뒷발은 들려서 `32 → 52`로 나오고, 4~0칸에는 뒷발이 `52 → 32`로 디디고 앞발이 들려 나온다. 다리 그림이 한 장뿐이라 깜빡이지 않는다. 걸음 5px/프레임 → `advance` 12. 크기: 모자 끝~발바닥 400 장면 px(호랑이보다 조금 작음). 화면 쪽(아래) 다리가 뒷다리라 겹칠 때는 뒷다리를 위에 그린다(`near: 'rear'`). 왼쪽 방향의 작은 `T2` 카드 글자는 반전된 채로 둔다(쓰이지 않는 방향이고 몇 px뿐).

### 남은 점

- 토끼 3~4칸(다리를 많이 민 지나가는 자세)은 두 다리가 겹쳐 보여 확대하면 경계가 조금 어색하다. 장면 크기에서는 다리가 바닥 쪽 흐림에 반쯤 가려 잘 안 보인다.
- 디딘 발 바닥 높이가 프레임마다 2~5px 달라 몸은 수평으로 가도 발이 살짝 뜨거나 묻힌다(호랑이와 같음).
- 두 캐릭터 모두 몸이 수평으로 미끄러지듯 가고 다리만 움직인다(호랑이와 같은 방식).
